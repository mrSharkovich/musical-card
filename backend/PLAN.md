# План разработки MVP-бэкенда

## Цель

Серверное хранение музыкальных открыток без регистрации: черновик открывается по секретной ссылке, а получателю отправляется отдельная публичная ссылка.

## Контракт API

1. `POST /api/projects` → `{ "editToken": "..." }`.
2. `GET /api/projects/{editToken}` → `{ "project": CardProject }`.
3. `PUT /api/projects/{editToken}` → `{ "ok": true }`.
4. `POST /api/assets` → `{ "url": "/api/media/draft/..." }`.
5. `POST /api/projects/{editToken}/publish` → `{ "publicId": "..." }`.
6. `GET /api/cards/{publicId}` → `scheduled` либо `ready`.

## Правила MVP

- `editToken` создаётся криптографически стойким способом и не передаётся получателю.
- Публикация сохраняет глубокую копию проекта; последующее редактирование черновика её не меняет.
- Доступ к медиа проверяется маршрутом API; до `opensAt` содержимое и файлы открытки не выдаются.
- Принимаются JPEG, PNG, WebP, GIF и проверяемые аудиоформаты; лимиты: 8 МБ для изображений и 15 МБ для аудио.
- Файловое хранилище — временное решение до подключения БД.
