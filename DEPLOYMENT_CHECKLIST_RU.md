# Перед публикацией в интернет — список оставшихся работ

Ни один ZIP не может сам настроить домашний роутер, Windows 11, VirtualBox, домен, выдачу сертификатов, резервные копии и внешнюю защиту. **Этот список обязателен перед публичным запуском.**

1. **Проверить Windows 11:** обновления Windows Defender и Python, выделенный непривилегированный пользователь сервиса, права NTFS на `backend/data/`, отключённые общие папки/буфер обмена/USB в VirtualBox, отсутствие RDP/SMB/управления VirtualBox через WAN.
2. **Изоляция:** сетевой мост VirtualBox через Wi-Fi **не** изолирует ВМ от домашнего LAN. Для защиты основной сети предпочтительны отдельная VLAN/сегмент/маршрутизируемая гостевая сеть с правилами firewall либо внешняя VPS.
3. **Запуск:** один процесс Uvicorn на `127.0.0.1:8001`. При Caddy на той же машине Uvicorn может использовать `--proxy-headers --forwarded-allow-ips 127.0.0.1`, только если Caddy перезаписывает внешний `X-Forwarded-For`, иначе IP лимитер может доверять поддельным значениям. За пределами Windows Firewall запретить 8001.
4. **Caddy и домен:** выпустить сертификат для подтверждённого домена, на WAN открыть только необходимые 80/443 для HTTPS и продления сертификатов, проверить редирект HTTP→HTTPS, включить современные TLS; не открывать 8001. Установить `TRUSTED_HOSTS=домен,localhost,127.0.0.1` и не принимать чужие Host.
5. **Защита на границе:** ограничение body uploads ~16 МБ, запросов/сек/IP и одновременных подключений через reverse proxy или другой edge; встроенный in-memory лимитер — не WAF и не защита от распределённого DoS.
6. **Секретные URL:** выключить access logs с полным путём и query, в том числе в Caddy; защитить журналы. API содержит редакторский токен в пути (`/api/projects/{token}`). Никогда не отправлять ссылки редактирования получателям.
7. **Тестирование:** проверить фото JPG/PNG/GIF/WebP, Voice/Music/микрофон в HTTPS, шаблоны, GIF, сохранение пропорций, фон, ссылки и отложенную публикацию **с другого устройства**. По HTTPS удостовериться, что файл закрытой открытки нельзя получить напрямую.
8. **Системный мониторинг:** место на диске, RAM/CPU, дата/время VM (NTP), ошибки сервера, резервные копии, ежемесячные обновления зависимостей/CVE и ручной восстановительный тест из backup.
9. **Очистка:** сначала запуск `python -m backend.app.cleanup --days 30 --dry-run` и проверка кандидатов, затем согласование сроков хранения. Открытки с будущим временем должны переживать очистку.
10. **Юридические требования:** опубликовать сведения о владельце сервиса, контакт для запросов о личных фото/голосовых сообщениях, политику конфиденциальности, срок удаления и порядок жалоб на нарушение авторских прав. Для CC BY и CC BY-SA сохранять атрибуции в готовых открытках; пользовательские файлы — ответственность загрузивших.

До завершения этих пунктов использовать только локальную тестовую сеть. При необходимости лучше развернуть сервис на отдельной VPS или использовать туннель, чем открывать домашний LAN.
