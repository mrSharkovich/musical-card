# Установка единой защищённой сборки Musical Card (Windows 11 VirtualBox)

**Папка проекта:** `C:\Users\vboxuser\Desktop\musical-card`  
**Тестовый адрес:** `http://192.168.1.102:8001` (только домашняя сеть).  
**Внимание:** до успешного тестирования НЕ открывайте порты на роутере и не запускайте сайт публично.

## 1. Резервная копия перед заменой

1. Остановите работающий Uvicorn (`Ctrl+C`).
2. Закройте редактор в браузере; дождитесь завершения последнего сохранения.
3. Сделайте **полную** копию всей папки `musical-card` на отдельный диск, обязательно включив `backend\data\`, `db\` и `.venv\`. Пример в PowerShell (при наличии места):

```powershell
$source = 'C:\Users\vboxuser\Desktop\musical-card'
$backup = 'C:\Users\vboxuser\Desktop\musical-card-BACKUP-' + (Get-Date -Format 'yyyyMMdd-HHmmss')
Copy-Item -LiteralPath $source -Destination $backup -Recurse
Write-Host "Сохранено: $backup"
```

**Не копируйте/восстанавливайте данные, пока сервер работает.** Проверьте, что копия действительно содержит прежние JSON и пользовательские файлы. Резервные копии содержат личные фото и голос — храните их конфиденциально.

## 2. Замена кода

Распакуйте **содержимое** ZIP в `C:\Users\vboxuser\Desktop\musical-card` с заменой одноимённых файлов. **Не удаляйте** существующие папки `.venv` и `backend\data`. Не заменяйте их содержимым из других проектов. Этот архив специально НЕ содержит `.venv` и пользовательские данные `backend\data`.

**Изменения в каталоге:** ресурсы `new-year-table`, `nunspeet-christmas-lights`, `hubble-ultra-deep-field` исключены из распространяемых файлов до проверки авторства/лицензии. Если старые открытки уже использовали их, замените такие фоны после обновления. Два первых раньше были активными.

**Совместимость старых публичных ссылок:** публикации, созданные старой версией, без поля владельца `editOwner`, продолжают отдавать текст/фигуры, но **их загруженные пользователем фото/аудио заблокированы** для устранения межпроектной утечки. Чтобы восстановить доступ к таким файлам, откройте старую открытку по её секретной **ссылке редактирования** и **опубликуйте её заново**. Получится новая публичная ссылка. Старые секретные ссылки редактирования продолжают работать. Автоматической небезопасной миграции прав нет.

## 3. Обновление зависимостей

Откройте PowerShell **в виртуальной машине**:

```powershell
cd "C:\Users\vboxuser\Desktop\musical-card"
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install --upgrade -r backend\requirements-dev.txt
.\.venv\Scripts\python.exe -m pip check
```

Это добавит **Pillow** для безопасной проверки изображений и обновит FastAPI, Starlette, Uvicorn и python-multipart. `httpx` нужен для тестов. Если установка завершилась ошибкой, **не запускайте новую версию**: пришлите текст ошибки.

Проверьте реальные версии:

```powershell
.\.venv\Scripts\python.exe -m pip show fastapi starlette uvicorn python-multipart Pillow
```

## 4. Автоматические тесты

```powershell
$env:PYTHONPATH="backend"
.\.venv\Scripts\python.exe -m unittest discover -s backend\tests -v
.\.venv\Scripts\python.exe -m unittest discover -s db\tests -v
```

В этом пакете **28** серверных тестов и **16** тестов каталога, итого **44**. На виртуалке число и итог должны быть такими же. Результат обоих запусков — `OK`.

## 5. Запуск только для тестирования в локальной сети

```powershell
$env:TRUSTED_HOSTS="localhost,127.0.0.1,192.168.1.102"
.\.venv\Scripts\python.exe -m uvicorn backend.app.main:app --host 0.0.0.0 --port 8001 --workers 1 --no-access-log --no-proxy-headers
```

Откройте на основном компьютере `http://192.168.1.102:8001`, нажмите `Ctrl+Shift+R`.

**Проверить вручную:**

- Новая открытка, изображение JPG/PNG/GIF/WebP; увеличение/уменьшение без обрезки; стикеры и фоны каталога.
- Добавление музыки, голосового файла, совместное воспроизведение и независимая громкость. Запись голоса через микрофон требует HTTPS либо localhost (на обычном LAN HTTP она не обязана работать).
- Редактирование, автосохранение, повторное открытие секретной ссылки; отмена/повтор, шаблоны, рисунки.
- Публикация сразу; ссылка открывается на другом устройстве.
- Публикация на будущее: по публичному URL видна только заглушка, файлы недоступны до назначенного времени.
- Подпись **«Авторы и лицензии использованных материалов»** под готовой открыткой с музыкой/фоном CC BY или CC BY-SA.
- Удаление пробной открытки из редактора; после удаления секретная и новые публичные ссылки недоступны.
- Старые черновики и старые опубликованные карточки: см. раздел о совместимости выше.

## 6. Откат при ошибке

Остановите Uvicorn, переименуйте неработающий каталог, восстановите всю копию из шага 1, затем установите старые зависимости из резервной копии `.venv` либо пересоздайте окружение со старым `requirements.txt`. **Не смешивайте старые и новые части** проекта при откате. До отката не удаляйте данные из новой версии, если уже успели создать важные открытки.

## 7. Только после успешных тестов

- Домен/DuckDNS, работающий DNS, Caddy TLS и `TRUSTED_HOSTS` с вашим настоящим доменом.
- Внутри ВМ запуск Uvicorn исключительно `127.0.0.1:8001` и один worker (поскольку файловая база и лимитер локальные).
- Caddy только на 443/80, Windows Firewall и роутер не должны выпускать наружу порт 8001. Не открывать RDP, SMB, VirtualBox UI из WAN.
- Дополнительный rate limit/WAF на внешней границе, лимит HTTP-тела, мониторинг диска, доступность, резервные копии, обновления Windows/Python.
- Для сетевого моста VirtualBox через Wi-Fi: виртуальная машина разделяет домашнюю сеть. Для строгой изоляции понадобится отдельная VLAN/сеть или хостинг вне дома; сама ВМ не обеспечивает полной защиты домашней сети.

См. `SECURITY_AUDIT_RU.md` и `LICENSES.md`.

### Дополнение о лимитере за HTTPS-прокси

После перехода на Caddy сетевой адрес каждого посетителя должен определяться только по **доверенному** `X-Forwarded-For`, присланному Caddy с `127.0.0.1`. Иначе все посетители получат общую квоту, либо злоумышленник сможет подменять IP. Эту часть проверим на реальной виртуальной машине после выбора домена и схемы подключения.
